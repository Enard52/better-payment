---
title: Multi-Tenant Credentials
description: Dynamic provider credentials per merchant for marketplaces and SaaS platforms.
---

<Since version="0.12.0" />

Marketplaces, e-commerce builders, and SaaS platforms process payments on behalf of hundreds or thousands of independent merchants. Each merchant holds their own contract and credentials with payment service providers (iyzico, PayTR, Akbank, Sipay, etc.).

Instead of manually constructing and managing thousands of `betterPayment()` instances, the `multiTenant` plugin dynamically resolves credentials per merchant, caches provider instances, and automatically tags operations and events with the originating tenant ID.

## Setup

```typescript
import { betterPayment, iyzico, paytr } from 'better-payment';
import { multiTenant } from 'better-payment/plugins';

const payment = betterPayment({
  providers: {
    iyzico: iyzico({ apiKey: 'fallback', secretKey: 'fallback' }),
  },
  plugins: [
    multiTenant({
      // Resolves tenant from request header, metadata, or conversationId
      tenant: (ctx) => ctx.headers?.['x-tenant-id'] ?? ctx.request?.metadata?.tenantId,

      // Loads credentials or provider instances from your database
      credentials: async (tenantId, provider) => {
        const merchant = await db.merchants.findById(tenantId);
        return {
          apiKey: merchant.iyzicoApiKey,
          secretKey: merchant.iyzicoSecretKey,
        };
      },

      // Factory mapping to instantiate providers from raw credentials
      providers: {
        iyzico: (creds) => iyzico(creds),
      },

      cache: {
        ttl: '10m', // Cache provider instances for 10 minutes
        maxSize: 5000,
      },
    }),
  ],
});
```

## Using `forTenant`

You can scope any payment operation directly to a specific merchant contract:

```typescript
// All operations automatically execute with shop-42 credentials
const result = await payment.forTenant('shop-42').createPayment({
  price: '150.00',
  paidPrice: '150.00',
  currency: 'TRY',
  paymentCard: { ... },
});

console.log(result.status);   // 'success'
console.log(result.tenantId); // 'shop-42'
```

Supported `forTenant` operations include:
- `createPayment`, `initThreeDSPayment`, `completeThreeDSPayment`
- `authorize`, `initThreeDSAuthorize`, `capture`, `voidAuthorization`
- `refund`, `cancel`, `getPayment`
- `saveCard`, `listCards`, `deleteCard`, `binCheck`, `installmentInfo`

## 3D Secure Callbacks

For 3D Secure payments, the bank redirects back to your callback URL. The plugin automatically detects the tenant ID if:
1. `conversationId` has the format `tenant:<tenantId>:<orderId>` or `<tenantId>::<orderId>`
2. The custom `tenant` resolver inspects the callback query or body.

```typescript
const init = await payment.forTenant('shop-42').initThreeDSPayment({
  price: '150.00',
  paidPrice: '150.00',
  callbackUrl: 'https://shop.com/api/pay/iyzico/callback',
  conversationId: 'tenant:shop-42:order-987',
  paymentCard: { ... },
});
```

When the bank posts the callback, the plugin automatically resolves `shop-42`, decrypts the signature with `shop-42` secret keys, and attaches `tenantId: 'shop-42'` to the callback response.

## Cache Management

Cached provider instances can be purged when merchant settings change:

```typescript
// Clear cache for a specific merchant
payment.tenants.clearCache('shop-42');

// Clear all cached provider instances
payment.tenants.clearCache();

// Inspect cache stats
const stats = payment.tenants.getCacheStats();
console.log(stats.size, stats.ttl);
```

## Options

| Option | Default | Description |
| ------ | ------- | ----------- |
| `credentials` | *required* | `(tenantId, provider) => Promise<PaymentProvider \| Record<string, unknown>>` |
| `tenant` | built-in resolver | Custom function resolving tenant ID from context, request, or headers |
| `providers` | — | Map of provider factory functions `(credentials) => PaymentProvider` |
| `cache.ttl` | `'5m'` | Duration before refreshing cached merchant provider instances |
| `cache.maxSize` | `1000` | Maximum number of cached instances before LRU eviction |
